## 问题与复核要点

- A 复现步骤：在默认方舟设置下提交 B01。SSE 只出现开始、报告生成、失败终态。异常为 `INTERNAL_ERROR` / `The model did not produce a valid test plan`。脱敏对照请求显示默认思考模式在 2048 输出预算处以 `length` 结束，正文为空。关闭思考后返回 605 字符的有效计划（两次对照用量分别为 4781/2845 Token，独立于实际 Run）。适配器对方舟主机默认关闭思考，规划截断时提供具体错误文案；报告直接展示错误和证据空状态。
- B 复跑步骤：改用唯一项目名，沿相同入口执行。截图证据 ID 为 `art_fdc3f9a42fba49b6a47cf7751f7acaba`，下载返回 `image/png`、4254 字节。多个检查点无匹配，轨迹中若干 `browser.inspect` 被判为 `INVALID_ARGUMENTS`。4gaBoards 启动时的 `BASE_URL` 是 `127.0.0.1:3000`，B 从容器别名访问，应用资源跨 origin 受浏览器策略限制。C 使用容器内部回环转发，让 Chromium 和人工浏览器都使用与站点配置一致的 origin。
- C 登录页的两个输入框在可访问树中均无名称。C 的填写尝试包含 `ELEMENT_NOT_FOUND`、`INVALID_ARGUMENTS` 和 `TOOL_TIMEOUT`。D 在明确给出登录控件的 CSS 定位器后成功填写并登录，随后未完成目标。独立 Chrome 会话分别检查项目卡片与侧栏链接，A、B、C、D 在刷新前后均未创建。报告页已通过 Chrome 验证显示 A 的具体失败原因。
- C 的截图 `art_38dc73be14a3428091437efc348a81f6` 通过 C5 返回 HTTP 200，共 34736 字节。Chrome 从报告面板打开图片，解码为 1280×720。这张截图不能证明创建成功。
- E 将登录、等待页面、截图、创建、返回首页和验证依次写入目标，实际仍在登录后提早结束。数据库只读查询确认 A–E 的目标项目共 0 条，业务判定与实际一致，B01 未验收通过。下一步排查 Agent 登录后提前结束的原因，随后核对项目创建后的两处证据及终点截图。
- D、E 轨迹复查：登录点击成功后均执行页面观察，先看到登录页，随后观察到包含 `Add Project` 的仪表盘。计划都有项目断言。之后没有新动作，直接进入最终 `browser.inspect`。两次只记录 4 个执行步骤，未到步骤或浏览器动作上限。最终检查调用成功，业务匹配为 false。旧报告覆盖了停止原因，无法区分模型主动停止和本地上下文拒绝。
- 修复：模型停止且仍有步骤预算时，如果近期有成功点击、当前给定检查点明确不匹配，允许一次带检查点反馈的继续机会。完成的检查点仍由引擎取证判定。失败报告保留原始停止原因；没有保存原始模型文本。离线回归 25 项通过，覆盖提前停止后的续跑及原有正反用例。
- F 使用相同的本机 4gaBoards 和有界面 Chromium，限定 18 个 Agent 步骤和 35 次浏览器动作。只读实时画面由本机网关 `/live/` 提供，每 750 ms 刷新一次。
