# 05 开放问题与风险

这些条目记录 v0.1 的实现基线与待决事项。执行验收时对照用例与预期记录实际结果。需求、架构和接口变更分别同步到 SRS 与验收、ADR 和正式契约。 [手工验收](04-acceptance.md)

## Q-001 v0.1 范围

验收场景由测试人员在自己的授权站点选择。浏览器场景库可以管理和提交场景模板，生成的测试计划直接进入执行。后续评审是否加入可编辑或待人工确认的计划。

## Q-002 公共接口与状态

FastAPI 从 HTTP 模型导出 OpenAPI，Vue 使用生成的类型；Worker 按 C2 将运行与判定映射到 C1。验收时用同一夹具核对正常结果、业务断言失败、技术异常和取消的详情、SSE 与报告。 [C1～C6](../contracts/README.md)

## Q-003 队列持久化与恢复

Worker 从 PostgreSQL 领取 `queued` 记录，通过执行令牌和心跳续租维护写入资格，并在心跳读取取消标记。过期或遗留的无租约运行收尾为 `WORKER_ERROR`。用 Worker 中断与重启演练核对租约收尾、旧执行者的资源清理和历史证据的可见性。 [C6](../contracts/database/c6-platform-persistence.md)

## Q-004 运行和用例隔离

同一 Run 中各用例使用独立 `BrowserContext`，平台 Worker 也为各 Run 使用独立 Chromium。浏览器会话隔离覆盖 Cookie 和页面会话。测试网站后端的账号和业务记录仍需由各夹具定义初始状态与重置方式。验收时交换登录用例的先后顺序，并并行复跑，检查是否依赖共享站点状态。

## Q-005 运行预算与基线

运行时已提供时间、用例数、步骤、动作、工具尝试、模型用量和并发等限制。记录代表性场景的实际用量、模型、环境和配置，再评估当前默认值。课程“35 次操作”的计数口径仍待确认，需与当前的每 Run 浏览器动作计数对照。 [C2 运行选项](../contracts/waata/c2-waata-python-api.md)

## Q-006 结果可信度

当前模型用于规划及选择浏览器动作，断言由支持的检查点和已登记的证据决定。手工验收时记录实际结果、证据缺口和有待支持的检查点类型。进一步评审是否需要语义断言以及相应的证据要求。 [验收判定](04-acceptance.md#ac-03-断言与失败归因)

## Q-007 证据和报告

平台以私有文件目录存放证据字节，PostgreSQL 保留元数据。大小上限与保留期可配置。结构化观察可交付，截图按目标策略启用和遮罩，原始 Playwright Trace 采集关闭。可选 Langfuse 记录运行追踪元数据。继续验证截图遮罩和到期行为，评审安全采集原始 Trace 的条件、报告导出范围及额外存储后端。 [C5](../contracts/artifacts/c5-test-evidence-artifacts.md)

## Q-008 授权目标和测试凭据

目标策略按 origin 声明允许的主体、浏览器动作和凭据引用。凭据值来自可信环境变量，浏览器根据策略限制实际操作。共享部署仍需明确由谁维护或审批目标配置、网络出口和有外部副作用的功能操作。 [后端运行设置](../apps/api/README.md#运行设置)

## Q-009 事件传递与重连

API 支持 Last-Event-ID、`after` 游标和保活，Vue 按 Run ID 和序号去重并在终态刷新详情。实际部署仍需验证断线、游标补读以及网关的缓冲和空闲超时。 [C4](../contracts/events/c4-test-run-events.md)

## Q-010 工程工具与流程

项目使用 uv 锁定 Python 工作区，前端使用 npm 锁文件。提交检查由根目录钩子配置管理。待团队确定 CI 必跑检查、人工验收记录的归档方式和主分支保护规则。 [前端说明](../apps/web/README.md) · [团队协作规约](../CONTRIBUTING.md)
