# 01 项目愿景

## 背景与目标

传统 Web 功能自动化需要为每条流程编写和维护脚本。页面文本、组件或布局变化后，测试人员常需要重新定位元素和检查执行过程。WAATA 允许使用自然语言表达测试目标，由系统在目标页面上选择适当的功能操作，并记录可供复核的执行结果。

目标用户是开发者和测试工程师。他们在拥有授权的开发或测试环境中验证指定的 Web 功能，也可在页面改动后复跑同一场景。使用者提供测试目标、预期行为、所需测试数据与目标环境的访问授权。

## v0.1 范围

以明确目标的 Web 功能测试为起点。用户可以直接创建任务，也可以在当前浏览器保存应用和场景，选中场景后批量提交。平台会排队执行、显示实时进度、受理取消，并保存报告和证据。独立 `waata` Python 包提供规划、浏览器执行、断言和报告能力，可在平台之外调用。

首轮验收使用同一个自建登录夹具的基准版和回归版。两者使用相同测试目标、凭据和预期，便于复核系统对有效凭据、错误密码和实际回归的判定。4gaBoards 创建项目用于说明跨模块数据流。三个上游网站可在需要时单独部署为功能测试目标。 [验收场景](04-acceptance.md) · [站点夹具](../testsites/README.md) · [4gaBoards 契约示例](../contracts/examples/README.md)

全站自主探索、通用视觉回归、压力测试、定时执行、测试项目管理和复杂团队权限属于后续范围。涉及生产数据或有外部副作用的操作，由团队明确授权边界后再纳入测试。

项目对成功的判断以预期行为与执行证据为基准。正常完成的运行可以发现目标站点回归，报告分别记录运行状态和测试判定。 [软件需求规格说明](02-requirements.md)
