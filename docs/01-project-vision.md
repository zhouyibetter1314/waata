# 01 项目愿景

## 背景与目标

传统 Web 功能自动化需要为每条流程编写和维护脚本。页面文本、组件或布局变化后，测试人员常需要重新定位元素和检查执行过程。WAATA 允许使用自然语言表达测试目标，由系统在目标页面上选择适当的功能操作，并记录可供复核的执行结果。

目标用户是开发者和测试工程师。他们在拥有授权的开发或测试环境中验证指定的 Web 功能，也可在页面改动后复跑同一场景。使用者提供测试目标、预期行为、所需测试数据与目标环境的访问授权。

## v0.1 范围

以明确目标的 Web 功能测试为起点。一次运行包含测试规划、浏览器执行、结果验证和报告。独立 Python 包承载完整流程，平台让用户提交任务、查看进度并复核报告。首轮验收使用自建演示站点的登录场景，涵盖有效凭据和错误密码。4gaBoards 创建项目场景用于展示跨模块契约。

全站自主探索、通用视觉回归、压力测试、定时执行、测试项目管理和复杂团队权限属于后续范围。涉及生产数据或有外部副作用的操作，由团队明确授权边界后再纳入测试。

项目对成功的判断以预期行为与执行证据为基准。详细要求见 [SRS](02-requirements.md)，首轮可复现的验证方式见 [MVP 与验收](04-acceptance.md)。
