# 02 软件需求规格说明

P0 为核心执行能力，P1 为平台集成。一次提交生成一个运行（Run）。运行内的用例（Case）通过步骤、断言与证据验证目标行为。运行状态记录执行生命周期，测试判定记录实际行为与预期的匹配结果。正常结束的运行可以包含失败断言。

## 功能需求

| ID | 优先级 | 实现要求 | 验收 |
| --- | --- | --- | --- |
| FR-001 | P0 | 接收目标 URL、自然语言测试目标和预期行为，为有效请求分配唯一 Run ID | [AC-01](04-acceptance.md#ac-01-提交与规划) |
| FR-002 | P0 | 规划包含目标、前置条件、预期行为和可执行检查点的用例 | [AC-01](04-acceptance.md#ac-01-提交与规划) |
| FR-003 | P0 | 使用 Playwright 在授权站点执行允许的功能动作并观察页面 | [AC-02](04-acceptance.md#ac-02-受控站点执行) |
| FR-004 | P0 | 以确定性检查和同用例证据判定实际结果，体现断言不符、执行受阻、证据不足及技术错误 | [AC-03](04-acceptance.md#ac-03-断言与失败归因) |
| FR-005 | P0 | 保存与 Run 关联的结构化结果，包括用例、步骤、断言、异常和证据引用 | [AC-04](04-acceptance.md#ac-04-报告与证据) |
| FR-006 | P1 | 分页查询运行和详情，按游标恢复进度事件，并申请取消排队或运行中的任务 | [AC-05](04-acceptance.md#ac-05-平台端到端) |
| FR-007 | P1 | 查询保存的报告、结构化观察及目标策略允许的遮罩截图 | [AC-04](04-acceptance.md#ac-04-报告与证据)、[AC-05](04-acceptance.md#ac-05-平台端到端) |

## 非功能需求

| ID | 质量属性 | 实现要求 | 验收 |
| --- | --- | --- | --- |
| NFR-001 | 可靠性 | 区分模型或浏览器异常、超时与取消，结束时清理运行持有的浏览器资源。服务重启后可继续领取排队任务并查询历史。失去执行者的运行按技术故障收尾 | [AC-05](04-acceptance.md#ac-05-平台端到端)、[AC-06](04-acceptance.md#ac-06-错误与资源边界) |
| NFR-002 | 可观测性 | 按 Run ID 关联报告、用例与步骤事件和证据。启用 Langfuse 时可查询对应的运行追踪元数据 | [AC-04](04-acceptance.md#ac-04-报告与证据) |
| NFR-003 | 可维护性 | Python 包支持独立调用，并通过依赖注入独立验证核心流程 | [AC-07](04-acceptance.md#ac-07-独立使用与可复现性) |
| NFR-004 | 授权与数据保护 | 浏览器边界执行 origin 和动作限制，各用例隔离浏览器会话，已知凭据和敏感页面值按证据与脱敏策略处理 | [AC-06](04-acceptance.md#ac-06-错误与资源边界) |
| NFR-005 | 可重复性 | 通过目标地址、前置条件、报告中的执行限制和证据引用复核。验收人员记录版本和测试数据基线 | [AC-07](04-acceptance.md#ac-07-独立使用与可复现性) |
| NFR-006 | 资源控制 | 限制运行时间、用例数、每用例步骤数、浏览器动作、工具尝试、模型用量与并发 | [AC-06](04-acceptance.md#ac-06-错误与资源边界) |

场景库保存在当前浏览器。JSON 导入和批量提交由前端处理，各场景独立提交并生成 Run。[前端](../apps/web/README.md) · [公共契约](../contracts/README.md)
