# 04 MVP 与验收

以下是 v0.1 的手工验收步骤和预期。每次验收记录项目修订、夹具版本、模型与有效配置、Run ID 和实际结果。跨模块字段与事件可参考样例。 [4gaBoards 契约示例](../contracts/examples/README.md)

## 测试夹具

1. 配置 WAATA 专用 PostgreSQL 数据库、受控模型服务、目标策略及夹具凭据。启动两个演示站点、API、Worker 和连接真实后端的 Vue。站点代码位于 `testsites/demo-app/`。 [启动和配置](../apps/api/README.md#本地登录夹具)
2. 打开 `/runs/new`，以 `http://127.0.0.1:3010/login` 为基准目标，以 `http://127.0.0.1:3011/login` 为回归目标。两次使用相同凭据引用 `demo_login_fixture`，密码值由 Worker 按目标策略解析。
3. 对两次运行都填写目标“验证有效密码与错误密码的登录行为”，预期填写“有效密码进入 `/dashboard` 且显示 `Signed in`，错误密码留在 `/login` 且显示 `Wrong password`”。回归版仅改变错误提示，两个版本均使用同样的预期值。

## AC-01 提交与规划

从 Vue 提交任务，核对 C1 返回 `202` 和可查询的 `run_id`。运行开始后检查计划事件，报告生成后核对有效密码与错误密码用例、前置条件、预期行为和关联检查点。独立调用时可从 `TestEngine.run` 的事件和结果查看相同关联。覆盖 FR-001、FR-002。 [C1](../contracts/http/c1-test-run-http-api.md) · [C2](../contracts/waata/c2-waata-python-api.md)

## AC-02 受控站点执行

在基准站点执行两个用例，核对步骤与对应的浏览器工具结果、后续页面观察及证据。两个用例各有独立浏览器会话，从登录页开始。检查有效密码的目标 URL 和已登录标记，以及错误密码的登录页 URL 和提示。覆盖 FR-003。 [C3](../contracts/tools/c3-browser-tools.md)

## AC-03 断言与失败归因

| 输入条件 | 预期状态和判定 | 验证点 |
| --- | --- | --- |
| 基准站点 | `succeeded` + `passed` | 两个用例均通过，URL 和界面状态均有证据 |
| 回归站点 | `succeeded` + `failed` | 有效密码用例通过，错误密码用例失败，报告标明提示内容的预期值和实际值 |
| 运行中发生浏览器故障 | `errored`，总体判定为空 | 运行详情给出技术错误码，可查询的部分报告保留已有结果 |
| 用例正常执行，部分检查点缺少证据，其余检查点均通过 | 该用例 `inconclusive` | 报告说明证据缺口，对缺乏充分证据的断言保留空值 |

覆盖 FR-004。判定的字段和值由 C2 与 C4 定义。

## AC-04 报告与证据

按 Run ID 打开报告，核对用例、步骤、断言预期与实际值以及异常。点击断言引用，核对对应的脱敏观察属于同一运行和用例。目标策略启用截图时，检查页面预览和配置的遮罩。选用 Langfuse 时，凭报告中的 `langfuse_trace_id` 找到该 Run 的追踪，核对模型、工具和判定元数据。原始 Playwright Trace 采集关闭。覆盖 FR-005、FR-007、NFR-002。 [C5](../contracts/artifacts/c5-test-evidence-artifacts.md)

## AC-05 平台端到端

1. 从运行列表打开任一 Run，核对状态、进度和时间线。刷新页面或恢复断开的网络连接后，核对已提交事件仍可按序显示，每条只应用一次。
2. 使用专门的 Run 验证排队和运行中取消。排队取消直接进入 `cancelled`。运行中取消先显示已受理，完成清理后进入 `cancelled`。核对每个 Run 仅有一个终态事件。
3. 重启 API 和 Worker，保持同一数据库和证据目录。重新打开原 Run 的详情、报告及未过期证据。用 `Last-Event-ID` 或 `after` 向事件端点提交先前记录的游标，核对只重放后续事件。使用已读终态的游标时，端点返回 `204`。
4. 在 `/scenarios` 保存或导入夹具模板，从列表提交选中的场景，并核对每项请求生成自己的 Run。刷新页面后核对模板仍可在当前浏览器打开。

覆盖 FR-006、FR-007 和平台事务验收。 [C4](../contracts/events/c4-test-run-events.md) · [C6](../contracts/database/c6-platform-persistence.md)

## AC-06 错误与资源边界

在专用夹具验证未授权目标被拒绝，浏览器实际执行也遵守 origin 和动作范围。用测试秘密标记复核请求展示值、模型输入、日志、报告、观察及启用的观测数据。验证同一运行的两个用例、并发的两个 Run 各用独立浏览器会话。

分别制造模型不可用、浏览器异常和运行超时，核对可识别的错误码及浏览器资源释放。取消时检查 Worker 清理后才发布终态。将预算和 Worker 并发配置调低，检查相应的时间、用例、步骤、动作、模型用量和并发边界。覆盖 NFR-001、NFR-004、NFR-006。 [后端运行设置](../apps/api/README.md#运行设置) · [C2](../contracts/waata/c2-waata-python-api.md)

## AC-07 独立使用与可复现性

从 Python 直接调用 `TestEngine`。可先用注入的模型和浏览器替身核对公共调用，再连接模型与本机夹具。重置同一版本的夹具后复跑，对照用例前置条件、验收记录中的环境版本、报告中的目标地址、执行限制和证据引用。覆盖 NFR-003、NFR-005。 [独立调用示例](../examples/README.md)
