# 04 MVP 与验收

状态为评审稿。独立 Python 包先验证完整测试流程，平台集成随后验证 Vue 提交、FastAPI 调度与前端复核。

## 测试夹具

使用 `testsites/demo-app/` 中计划实现的自有演示站点。验收前准备可以重置的测试账号和两个站点版本。基准版本允许有效凭据进入控制台，错误密码留在登录页并显示错误提示。回归版本把错误密码分支的提示改为与预期不一致的内容，用于验证产品回归判定。

对两个版本使用相同测试目标、凭据夹具和预期。测试目标为验证登录功能。有效凭据应进入控制台并显示已登录状态，错误密码应停留在登录页并显示约定的错误提示。账号和密码从测试夹具取得。

## AC-01 提交与规划

向核心入口提交目标 URL 和自然语言任务，验证系统关联 Run ID，并能生成有效凭据与错误密码两个用例。每个用例列出前置条件、预期行为及可观察的验证点。平台版本还验证从 Vue 提交后能获得可查询的任务标识。覆盖 FR-001、FR-002。

## AC-02 受控站点执行

在基准站点执行两个用例，确认步骤记录中有浏览器动作、操作结果和后续页面观察。用例从各自所需的登录前置状态开始。对有效凭据检查 URL 与登录状态标记，对错误密码检查登录页及提示内容。覆盖 FR-003。

## AC-03 断言与失败归因

| 输入条件 | 预期判定 | 验证点 |
| --- | --- | --- |
| 基准站点，有效凭据 | 用例通过 | 控制台 URL 和已登录状态均有证据 |
| 基准站点，错误密码 | 用例通过 | 登录页和预期错误提示均有证据 |
| 回归站点，错误密码 | 用例失败 | 报告标明提示内容的预期值和实际值 |
| 浏览器故障或观测缺失 | 执行错误或无法判定 | 报告说明技术异常或证据缺口，断言结论与运行状态可分别查看 |

覆盖 FR-004。判定的字段和值由 C2 与 C4 定义。

## AC-04 报告与证据

用 Run ID 打开结构化报告，逐条检查用例结果、步骤、预期与实际值、异常和证据引用。选择一条断言并通过同一 Run ID、用例 ID 或步骤 ID 找到对应的观察与 Trace。使用高层运行记录复核流程。覆盖 FR-005、NFR-002。

## AC-05 平台端到端

在 Vue 提交同一登录场景，检查 FastAPI 返回可查询的 Run ID。Worker 通过 WAATA 执行，前端可看到进度、最终报告与授权的浏览器证据引用。对回归版本确认技术运行完成后仍能展示失败的业务断言。覆盖 FR-006、FR-007。

## AC-06 错误与资源边界

使用测试替身注入模型异常、浏览器异常、取消与超时，分别确认运行进入可识别的结束状态并释放 BrowserContext。通过受控夹具验证超出授权范围的导航被拒绝，同时运行的两次测试会话互相隔离。用测试秘密标记检查日志、报告与 Trace 的脱敏行为。将预算配置设为便于触发上限的值，验证时间、用例数量、步骤、模型用量与并发边界。覆盖 NFR-001、NFR-004、NFR-006。

## AC-07 独立使用与可复现性

从 Python 调用核心包，分别使用 Fake LLM、Fake BrowserAdapter 和受控站点验证测试流程。重置夹具并复跑同一场景，依据报告保存的环境、有效配置和证据引用复核断言。覆盖 NFR-003、NFR-005。
