# 05 开放问题与风险

团队评审时为各条目指定负责人和决策时间。确定需求后更新 SRS 与验收条目，确定架构后记录 ADR，确定接口后更新对应契约。

## Q-001 v0.1 范围

评审登录以外的功能是否进入首版，以及测试计划是否需要人工确认或编辑。用首条端到端场景的交付成本决定扩展范围。

## Q-002 公共接口与状态

由前端、后端与核心包共同确认运行标识的归属、生命周期和用例判定字段、错误映射与取消交互。用同一个 Mock 场景验证三层对状态含义的理解一致。

## Q-003 队列持久化与恢复

确认进程内队列是否满足首版部署，服务重启如何处理已排队与运行中的任务，以及取消如何传递到浏览器执行。用重启和中途取消演练验证资源能清理、状态能解释。

## Q-004 运行和用例隔离

运行之间采用独立浏览器会话。评审同一 Run 中用例如何重置登录态和测试数据，避免顺序依赖。用交换两个登录用例的执行顺序与并行复跑验证隔离行为。

## Q-005 运行预算与基线

先记录代表性场景的执行时间、步骤数、模型用量和并发资源占用，再确定默认值和上限。记录模型、环境和数据条件，验证达到上限时任务如何收尾。

## Q-006 结果可信度

确定何时允许语义判断、证据缺失如何归类、模型结果如何与确定性断言一起呈现。用正常站点、回归站点和执行异常建立对照。

## Q-007 证据和报告

共同评审存储后端、保留期限、证据引用授权与报告导出范围。确认截图、Trace 和报告中可保存的敏感数据范围及脱敏方法。

## Q-008 授权目标和测试凭据

明确调用方如何证明目标授权、如何配置允许的域名与动作、如何提供测试凭据。使用受控站点检查重定向与跨域导航的处理，并明确有外部副作用的操作如何审批。

## Q-009 事件传递与重连

确认事件类型、顺序、断线重连、去重和终态查询机制。用 Mock 事件中断和重复投递验证 Vue 展示最终能与后端一致。

## Q-010 工程工具与流程

团队评审 Python 的 Ruff 与 pytest、前端的包管理器、ESLint 与类型检查，以及分支保护和 CI 基线。接入工具后记录对应模块的实际命令。
