## 系统架构

```text
Vue 工作台 ──C1 任务/报告──> FastAPI ──C6──> PostgreSQL 队列和运行记录
     ↑ C4 事件 / C5 证据                        │
     └──────────────────── Worker <────────────┘
                              │ C2
                              ▼
                  WAATA TestEngine：规划 → 执行 → 验证 → 报告
                       │ 模型决策                │ C3 浏览器动作
                       ▼                         ▼
                OpenAI 兼容模型接口      Playwright → 4gaBoards
```

模型决定业务动作；引擎执行检查点、采集终点截图并引用证据。平台存储报告和事件，C5 负责读取 PNG；本机 `/live/` 显示有界面 Chromium，不是回放录像。

## 技术修复、复现与局限

- 定位：限定仪表盘/侧栏、卡片与列表的作用域；保留批准的自定义控件和模板名，降低同名按钮歧义。
- 执行：自动观察页面状态；表单可在同轮填写与保存；模拟 Move 提交后点击超时，验证不重复发送有副作用的请求。
- 判定和证据：按页面区域分别断言；跨板先验源后验目标；引擎保存截图，通过 C5 供网页预览。报告区分运行状态、业务判定和技术异常。
- 中期离线验收未调用模型；后续 B10 已取得单请求真测通过，不计入开头的 7 个通用模式历史通过。B06 仍缺新的真实模型通过；B05 原始判定未被覆盖。B11–B13 未扩展 C3，不提供模型任意文件路径或下载访问。短句稳定性留到中期后；正式未发放的场景不报通过。网页报告尚未持久化提供方 Token，原始 Playwright Trace 未开启；现有轨迹以工具事件和观察证据为主。
- 若中期后要把 B11–B13 纳入原生 Agent，先协调 C3：拖拽仅接受当前页的两个已验证定位器；下载只回传同源、限大小的受控证据引用；上传只接受预登记的同版本夹具 ID。现阶段遵循手册的脚本/人工操作与 WAATA 后续观察分开记录。
